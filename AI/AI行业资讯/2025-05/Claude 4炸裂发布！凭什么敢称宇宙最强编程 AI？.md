# Claude 4炸裂釋出！憑什麼敢稱宇宙最強程式設計 AI？

5 月 23 日，Claude 官方宣佈推出下一代 Claude 模型：Claude Sonnet 4 和 Claude Opus 4，直接 **在全世界的 AI 圈掀起了新的風暴**！

據官方稱，Claude Opus 4 是 **世界上最好的程式設計模型**，在複雜、長期執行的任務和智慧體工作流程中具有持續效能，能夠連續工作數小時。據說有家日本公司使用它重構一套複雜的開源專案程式碼，結果它自主執行了 7 個小時，一直源源不斷地生成程式碼。

好傢伙，這永續性，都快能平替我們標準的 8 小時工作制了。以後我上班就開啟 AI 工具讓它自己生成程式碼，只要下班前檢查一下，就可以愉快下班了，真是充實且摸魚的一天啊！

![](https://pic.yupi.icu/1/1748049116801-cdfba9b0-ddec-4f01-b502-20490c50bc26.png)

Claude 4 一出現，直接為程式設計、高階推理和 AI 智慧體設立了新標準，達到 SOTA！

SOTA（State of the Art）是一個典型的網際網路黑話，常用來描述在某一特定領域內當前最佳的技術。

如圖，Claude 4 模型在 SWE-bench Verified 上領先，這是一個評估真實軟體工程任務效能的基準。

![](https://pic.yupi.icu/1/1747986906326-011c53e7-a1be-4a5f-a907-c570dfa53da5-20250524120720364.png)

Claude Sonnet 4 模型則是對 Claude Sonnet 3.7 的重大升級，在程式設計和推理方面表現更優異。雖然在大多數領域不及 Opus 4，但它也吊打了其他大模型，提供了能力和實用性的最佳組合，而且最關鍵的是 **對免費使用者開放**。

![](https://pic.yupi.icu/1/1747986915100-240318d1-19ce-4c7e-b6c2-f4e9e1e4886c-20250524120720453.png)

作為一個一直依賴 AI 程式設計的中毒患者，3.7 已經讓我很爽了，4 這個大版本不得起飛了啊？！想想當年的 GPT-3 和 GPT-4 的差距，直接把我的期待值拉滿了，下面我帶大家一起來試試效果。

## Claude 實戰

Claude 的使用非常簡單，直接進入官網（[claude.ai](https://claude.ai/)）就可以免費使用 Claude Sonnet 4 模型了：

![](https://pic.yupi.icu/1/1748054205184-19a24053-dd9a-4128-a072-0d3e031c2646.png)

如果你想用 Claude 來程式設計、生成網站，建議還是選擇專業的 AI 開發工具 Cursor，也已經第一時間整合了 Claude 4 系列模型。

![](https://pic.yupi.icu/1/1748054309771-fc7782f4-3c98-45e0-b276-b314b638a163.png)

下面魚皮將使用 Cursor 帶大家開發 3 個不同型別的網站專案：

- 工具類網站：檔案格式轉換工具
- 休閒娛樂類：連連看小遊戲
- 企業實用類：科技公司官網

有些博主只是單純測試使用 claude 4 來生成網站的效果，其實並不能體現出大模型進化了多少。而魚皮針對每個專案將分別採用 claude-3.7-sonnet、claude-4-sonnet 和 claude-4-opus，利用相同的 Prompt 提示詞進行生成，從而對比效果。



### 1、檔案格式轉換工具

首先準備一段 Prompt，這裡我們不使用過於專業的 Prompt，給 AI 足夠的發散空間和創作自由，讓他們自己來完成任務，更容易看出差距。

```plain
請生成一個《檔案格式轉換工具》網站，實現常見檔案格式轉換功能：
- 支援圖片、文件、音訊等格式的轉換
- 上傳檔案後選擇目標格式，點選轉換按鈕
- 展示轉換進度，完成後可以讓使用者下載

設計要求：
- 現代簡潔風格，主色調使用藍色
- 響應式佈局，適配手機和桌面
```

在 Cursor 中選擇對應的大模型、以及 Agent 智慧體模式，然後執行 Prompt：

![](https://pic.yupi.icu/1/1748054782941-36a20b14-52cb-49c5-b84f-f25f4fa46fcb.png)

等待一段時間後，就可以看到生成的效果了。比較坑的一點是，目前 Claude 4 Opus 模型過於火爆，一直提示說使用的人太多。。。本來我昨天就想發教程了，但就是卡在這一步，直到今天早上 8 點多才能正常使用。

![](https://pic.yupi.icu/1/1748054838846-ce6a7ae0-ebf5-47bb-a15b-c258412abe32.png)

我們將分別從生成 **程式碼的結構、網站的介面、網站的功能** 這 3 個角度來對比大模型的程式碼生成效果。

#### 程式碼結構對比

claude-3.7-sonnet 使用了 Next.js 前端框架技術來生成程式碼，生成了一個較為複雜的專案；而 claude-4-sonnet 和 claude-4-opus 直接使用最基礎的前端三件套（HTML + CSS + JavaScript）完成了專案。

![](https://pic.yupi.icu/1/1748055308007-48020e0f-3055-40b8-a9f4-2090cf8ec92c.png)

單看專案結構我們很難評判誰做的更好，因為有時候高階的功能往往只需要簡單的技術實現，less is more。



#### 網站介面對比

每個模型生成的網站都很簡潔，效果還不錯。但我會更喜歡 claude-4-sonnet，因為它給出了更多的引導資訊，比如支援的轉換格式等。

![](https://pic.yupi.icu/1/1748055697162-ea03506c-b109-475d-b15a-d9cc2a8f70d2.png)

選擇一個檔案後，claude-4-sonnet 和 claude-4-opus 生成的網站出現了動態互動效果，顯示出了待轉換的檔案，並且提示使用者要選擇目標格式。而且我注意到一些小細節，比如檔案大小的展示更精確了、選擇格式的 UI 也更好看。

![](https://pic.yupi.icu/1/1748055843229-9f4d4bb8-1395-4d8f-9ee8-77af572b6939.png)

轉換成功後，顯然 claude-4-sonnet 和 claude-4-opus 的成功提示和下載按鈕更明顯，高下立判！

![](https://pic.yupi.icu/1/1748056009117-e40e7bf9-bea8-41a3-aaa4-3d52c67d842b.png)

#### 網站功能對比

比較遺憾的是，所有模型生成的網站都只是有個“殼”，雖然輸出了 “檔案轉換成功”，但實際上只是改了檔案的字尾名而已，並沒有真的轉換格式。看下程式碼就知道了：

![](https://pic.yupi.icu/1/1748056469598-718d301b-da62-4fcc-b633-87b8b63f4534.png)

有意思的是，如果我上傳一個不支援的格式，claude-3.7-sonnet 會給出弱弱的警告；claude-4-sonnet 會給出更強力的彈窗警告；而 claude-4-opus 可以說是死鴨子嘴硬，我可以繼續選擇轉換格式，它也裝作能處理的樣子，還給我提示轉換成功。

![](https://pic.yupi.icu/1/1748056242227-9aa2dab7-41b1-437f-88b7-ccb74ae0bf99.png)

畢竟只是改個字尾而已，這麼玩當然什麼格式都能轉換了！你們說 claude-4-opus 這樣算是更智慧麼？



### 2. 休閒連連看遊戲

首先準備一段 Prompt，交給 Cursor 去執行：

```plain
請建立一個《連連看》遊戲網站，實現功能：
- 玩法遵循經典的連連看遊戲玩法，相同圖示可消除
- 計時系統和簡單得分機制
- 提供一些道具，增加遊戲趣味性

設計要求：
- 活潑可愛風格
- 響應式設計，適配不同裝置
- 新增圖示消除動畫和道具特效
```



#### 程式碼結構對比

跟生成檔案格式轉換工具類似，claude-3.7-sonnet 使用了 React 前端框架技術來生成程式碼，生成了一個較為複雜的專案；而 claude-4-sonnet 和 claude-4-opus 直接使用最基礎的前端三件套（HTML + CSS + JavaScript）完成了專案。

![](https://pic.yupi.icu/1/1748056960115-744a9731-0049-41c5-9e6b-616c6aca6c00.png)

看到這裡，我開始相信了：高階的功能往往只需要簡單的技術實現，less is more！



#### 網站介面對比

每個模型都理解了任務，生成出了經典連連看遊戲的頁面，都顯示了得分、時間和道具。但是介面美觀度高下立判啊！claude-3.7-sonnet 生成的遊戲帶著一股土味兒，而 claude-4-sonnet 和 claude-4-opus 介面都很軟萌 Q 彈，風格也比較接近，不愧是同系列的模型。

![](https://pic.yupi.icu/1/1748057128402-f6b13ee2-4092-453c-bffe-e82b34e50f4e.png)



#### 網站功能對比

所有模型生成的遊戲都是能正常操作的，可以消除圖案相同的方塊，也可以使用提示、洗牌、停止計時、炸彈等道具。但是 AI 對連連看遊戲的理解好像有點問題，比如下面這種情況，我記得是能消除的吧？但是生成的遊戲無法順利消除。。。

![](https://pic.yupi.icu/1/1748057414393-615b510b-8aec-436c-ae84-cc1d31f2b341.png)

所以功能上算是 3 個大模型打平了。但說真的，能透過一個 Prompt 提示詞、花幾分鐘就生成出這種效果，已經很強了。這哪怕讓一個精通前端的大佬來寫，最少也得花幾個小時吧？



### 3. 科技公司官網

我們再來一個企業開發的需求，幫魚皮自己的公司做個官方網站。準備一段 Prompt，交給 Cursor 去執行：

```plain
請為《魚鳶網路》公司建立一個簡潔的官方網站，展示公司資訊：
- 魚鳶網路成立於2023年，是一家專注於程式設計教育、創新產品研發、科技自媒體等領域的新興網際網路企業。
- 旗下自研產品程式設計導航、面試鴨、老魚簡歷、程式碼小抄、剪下助手、演算法導航等為使用者的工作和生活提供了更高效、易用的技術工具。專業程式設計學習交流網站程式設計導航為廣大程式設計愛好者及從業人員提供了程式設計學習、專案實戰、求職交流的全鏈路服務。
- 我們致力於透過科技創新，提升使用者在學習、工作、生活中獲取資訊的效率，讓技術更好地服務於每一個人。

設計要求：
- 專業商務風格，簡潔大氣
- 響應式佈局，移動端友好
```

這個需求其實比前面 2 個簡單多了，AI 也很快完成了任務。



#### 程式碼結構對比

這次的生成結果可就有意思了，claude-3.7-sonnet 和 claude-4-sonnet 直接使用最基礎的前端三件套（HTML + CSS + JavaScript）完成了專案，而 claude-4-opus 卻使用了 React 前端框架技術來生成程式碼，並且把一個簡單的頁面拆分成了很多個小元件。

![](https://pic.yupi.icu/1/1748057919666-0a068e65-a264-481a-bb53-f8c8027733cc.png)

出現這種情況也很正常，畢竟 AI 生成是具有一定隨機性的，我們還是來看看效果如何。



#### 網站介面對比

所有大模型生成的介面都是支援響應式的，從移動端小屏來看沒有明顯的差別：

![](https://pic.yupi.icu/1/1748058152472-9afdd0b3-58f1-458c-a3f0-e6d7a0faefda.png)

但是 PC 端大屏的區別就很明顯了，從 “關於我們” 板塊就能看出，claude-4-sonnet 和 claude-4-opus 生成的頁面明顯具有更多的細節，讓網站內容更充實。這波又是新模型的勝利~

![](https://pic.yupi.icu/1/1748058338558-466e055c-d08d-4b0d-bb98-e5107a30184e.png)



## 總結

透過上面三個例子，我個人感覺 claude-4-sonnet 和 claude-4-opus 從生成效果上 **幾乎是完勝** claude-3.7-sonnet 的。而且新版本的模型更聰明，不僅預設會選擇更簡單的技術來實現需求，而且還補充了更多的內容細節、更美觀的樣式和更自然的互動。

可惜現在用新模型的人比較多，生成程式碼時會遇到連線失敗、或者讓我等等的情況。建議大家早上 8 點多的時候使用，親測這個時候比較快~

對了，還得提醒一下，目前使用 claude 4 系列模型是按照 token 計費的，Claude 官方給出的價格是 Opus 4 每百萬 token 15/75美元（輸入/輸出），Sonnet 4 為 3/15 美元。而在 Cursor 中使用 Opus 4 是按 token 計費，使用 Sonnet 4（非 MAX 版本）是按照請求數計費，目前還有 75 折，一個請求大概是 0.04 美元。

![](https://pic.yupi.icu/1/1748059004335-70d84599-d7c6-4b3c-b682-7fa32f15a05c.png)
