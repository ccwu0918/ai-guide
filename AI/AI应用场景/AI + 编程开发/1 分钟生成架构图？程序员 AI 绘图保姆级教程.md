## 🖌️ 魚皮的 AI 畫圖秘術

雖然目前主流的 AI 大模型和工具都能實現畫圖功能，但我強烈建議使用 **Cursor 工具搭配 Claude 4 大模型**，效果最佳。

在開始之前，我們先了解一下 AI 畫圖的本質：**其實就是讓 AI 生成各種繪圖工具能夠理解的文字程式碼**，然後將這些程式碼匯入到對應的工具中進行渲染。這樣就能夠藉助 AI 的創意和工具的能力自由地生成圖片。

![](https://pic.yupi.icu/1/1748414656182-9580e13e-97bd-4013-8361-ee19b200c0f7.png)

下面來介紹幾類 AI 畫圖方法：

### 一、文字繪圖

文字繪圖是最受高階程式設計師歡迎的畫圖方式，透過簡單的文字描述就能生成專業的技術圖。主流的文字繪圖語言包括 **Mermaid** 和 **PlantUML**，它們各有特色，適用於不同的場景。

#### 1、Mermaid - 最流行的文字繪圖工具

Mermaid 是目前最流行的文字繪圖工具，語法簡單直觀，被 GitHub、語雀等大平臺原生支援。無論你是要畫軟體架構圖、業務流程圖，還是資料庫 ER 圖、Git 分支圖，Mermaid 都能輕鬆搞定。

讓我們先來畫一個使用者登入流程圖，只需要給 AI 這樣的提示詞：

```plain
請用 Mermaid 語法幫我畫一個使用者登入流程圖，包含以下步驟：
1. 使用者輸入賬號密碼
2. 前端校驗格式
3. 傳送請求到後端
4. 後端驗證使用者資訊
5. 如果驗證成功，生成 token 返回
6. 如果失敗，返回錯誤資訊
7. 前端根據結果跳轉頁面或顯示錯誤
```

放到 Cursor 等 AI 工具中執行：

![](https://pic.yupi.icu/1/1748415863293-79af3d1d-153d-462c-9dd7-ec63eaf6a3dd.png)

AI 會生成這樣的程式碼：

```
flowchart TD
    A[使用者輸入賬號密碼] --> B{前端格式校驗}
    B -->|格式正確| C[傳送登入請求到後端]
    B -->|格式錯誤| D[顯示格式錯誤提示]
    C --> E{後端驗證使用者資訊}
    E -->|驗證成功| F[生成Token]
    F --> G[返回Token給前端]
    G --> H[前端儲存Token]
    H --> I[跳轉到主頁]
    E -->|驗證失敗| J[返回錯誤資訊]
    J --> K[前端顯示錯誤提示]
    D --> A
    K --> A
```

然後你就可以把程式碼複製到 Mermaid 渲染工具中，比如寫作工具語雀支援新增文字繪圖元件：

![](https://pic.yupi.icu/1/1748414852734-6d3b6a1c-c2e8-4454-8e1b-57415f204bab.png)

然後就會出現一個繪圖框，在左側貼上文字程式碼，右側選擇對應的繪圖語言，就能看到效果了：

很多 Markdown 編輯器也天然支援 Mermaid 繪圖的渲染，比如 Typora：

![](https://pic.yupi.icu/1/1748415033938-862e8c79-5e83-40ae-a50a-ddd1a56033cd.png)

有很多支援 [Mermaid 渲染的網站](https://mermaid-live.nodejs.cn/edit)，還可以匯出為 PNG 等格式的圖片：

#### 2、PlantUML - 專業的 UML 繪圖工具

PlantUML 是另一個強大的文字繪圖工具，特別擅長繪製 UML 圖、時序圖和系統架構圖。它的語法相對 Mermaid 更加專業和規範，生成的圖表也更加精美。

讓我們用 AI + PlantUML 畫一個經典的訂單系統類圖，給 AI 的提示詞如下：

```plain
請用 PlantUML 語法幫我畫一個訂單系統的類圖，包含：
- Order 類：訂單ID、使用者ID、總金額、狀態、建立時間
- OrderItem 類：商品ID、數量、單價
- User 類：使用者ID、使用者名稱、郵箱
- Product 類：商品ID、名稱、價格、庫存
展示它們之間的關聯關係
```

AI 會生成專業的 PlantUML 程式碼，同樣放到語雀的文字繪圖、或者 [PlantUML 渲染網站](https://www.plantuml.com/plantuml/uml/) 中，都可以看到效果：

![](https://pic.yupi.icu/1/image-20250530125534018.png)

PlantUML 還特別適合畫複雜的時序圖和系統架構圖。比如一個完整的登入時序圖：

#### 其他文字繪圖工具

除了 Mermaid 和 PlantUML，還有 **Flowchart** 和 **Graphviz** 等文字繪圖工具。為了幫大家更好地選擇，我整理了這四種工具的對比：

| 特性         | **Mermaid**              | **PlantUML**      | **Flowchart** | **Graphviz**       |
| ------------ | ------------------------ | ----------------- | ------------- | ------------------ |
| **圖表型別** | 流程圖、時序圖、甘特圖等 | UML全系列、架構圖 | 流程圖        | 各類圖表，極其靈活 |
| **語法難度** | 簡單直觀                 | 中等，UML規範     | 非常簡單      | 較複雜             |
| **生態支援** | GitHub/GitLab原生支援    | 需要外掛支援      | 一般          | 廣泛支援           |
| **定製能力** | 中等                     | 高                | 低            | 極高               |
| **適用場景** | 日常文件配圖             | 專業架構設計      | 簡單流程說明  | 複雜網路拓撲       |
| **學習成本** | 低                       | 中                | 極低          | 高                 |

我的建議是，日常使用選 Mermaid，因為它語法簡單、平臺支援好；如果要畫專業的 UML 圖，就選 PlantUML。如果想生成複雜的網路拓撲圖，可以選擇 Graphviz，支援更復雜的定製能力。

### 二、網頁繪圖

網頁繪圖是一種非常自由靈活的繪圖方式。本質上是 “圖片即網站” —— 透過生成包含視覺化元素的網頁程式碼，在瀏覽器中渲染出各種圖片，而且可以實現靜態圖片無法做到的互動效果和動畫展示。

#### 1、原生網頁繪圖

利用網站開發的核心技術（HTML + CSS + JavaScript），我們可以生成各種型別的圖表。這種方式雖然不是傳統意義上的繪圖，但效果可能會超出預期。還可以藉助各種第三方視覺化庫（如 ECharts、D3.js 等）來增強效果。

舉個例子，當需要展示資料時，AI 可以利用 Apache ECharts 等視覺化庫生成專業的資料大屏。給 AI 的提示詞如下：

```plain
請生成一個資料視覺化大屏頁面，展示電商平臺的實時資料：
1. 頁面佈局：深色背景的大屏風格，分為頭部標題和多個資料展示區域
2. 包含以下圖表：
   - 實時銷售額（動態數字翻牌效果）
   - 各品類銷售佔比（餅圖）
   - 24小時銷售趨勢（折線圖）
   - 熱銷商品TOP10（柱狀圖）
   - 使用者地域分佈（中國地圖熱力圖）
3. 使用 ECharts 實現，要有動畫效果
4. 響應式佈局，適配不同螢幕
```

AI 會生成完整的網站，包含各種圖表，還是挺炫酷的吧~

![](https://pic.yupi.icu/1/1748417511003-49c81cc8-618e-4810-b94d-ebcfbb48885d.png)

你可以直接按需截圖，得到圖片；還可以透過 [Codepen](https://codepen.io/) 等網站執行工具將生成的網站快速分享給其他人。

![](https://pic.yupi.icu/1/1748417620327-fb4d8e79-c9f1-4b4d-a362-4c85437b8d02.png)

同理，AI 還能快速生成產品原型圖，特別適合快速驗證想法。給 AI 的提示詞如下：

```plain
你是一位專業的 UI 設計師，請生成一個移動端電商APP的完整原型圖，要求：
1. 使用 HTML+CSS 實現，風格簡潔現代
2. 在同一個 HTML 頁面中生成所有的原型頁面，平鋪排列
3. 生成的原型圖是可以直接提供給前端程式設計師進行開發的
```

#### 2、SVG 向量圖繪製

SVG 是可縮放的向量圖形，SVG 影象可以無限縮放而不失真，非常適合繪製 UI 素材、Logo 圖示、圖形插畫、技術架構圖、流程圖等需要無損縮放的圖片。

SVG 檔案本質上是 XML 格式的文字程式碼，可以直接嵌入網頁或匯入各種設計工具。

讓我們用 SVG 繪製一個系統架構圖，給 AI 的提示詞如下：

```plain
請生成一個 SVG 格式的系統架構圖，展示一個典型的三層架構：
- 展示層：Web 前端、移動端 App
- 業務層：API 伺服器叢集（3個節點）
- 資料層：主從資料庫、Redis 快取
要求：
- 使用不同顏色區分各層
- 新增連線線表示資料流向
- 圖形美觀，配色專業
```

AI 生成的 SVG 程式碼可以直接嵌入網頁或匯入設計工具，也可以儲存為 SVG 檔案直接雙擊在瀏覽器內開啟。效果還不錯吧~

![](https://pic.yupi.icu/1/1748419703308-c3e3ab06-bfd0-4d3e-8bd9-6315fe9e3dde.png)

使用 SVG 的另一個優點是可以精確控制每個元素的位置、大小和樣式，甚至能新增動畫效果，讓圖片更加生動。

### 三、思維導圖

AI 可以幫我們快速生成精美的思維導圖，並且能夠匯出為專業思維導圖軟體支援的格式，便於我們在學習和工作中梳理知識。

我用的比較多的思維導圖軟體是 XMind，支援豐富的樣式和主題。

可以透過 AI 直接生成 XMind 格式的思維導圖程式碼，提示詞如下：

```plain
請幫我生成一個關於"微服務架構設計"的思維導圖，要求生成可以匯入 XMind 軟體的格式。
注意，XMind 檔案實際上是一個 ZIP 壓縮包，需要包含多個必要的檔案。

導圖內容包含以下要點：
1. 服務拆分原則
   - 單一職責
   - 服務自治
   - 介面明確
2. 通訊機制
   - 同步通訊（REST、gRPC）
   - 非同步通訊（訊息佇列）
3. 服務治理
   - 服務註冊與發現
   - 負載均衡
   - 熔斷降級
```

生成的效果還不錯，還可以在軟體中進一步美化思維導圖的樣式，圖片太長了就給大家看一部分吧~

![](https://pic.yupi.icu/1/1748421899721-db05c840-44ac-439e-bfd3-a012a3631298.png)

不過我更建議讓 AI 生成 Markdown 格式的思維導圖，因為 Markdown 格式更通用，方便在各種文件工具中使用。給 AI 提供下面這段提示詞：

```plain
請將上述微服務架構內容整理成 Markdown 格式的思維導圖，使用縮排表示層級關係
```

AI 會生成這樣的 Markdown 格式：

```java
# 微服務架構設計

## 服務拆分原則
- 單一職責
  - 每個服務只負責一個業務功能
  - 高內聚低耦合
- 服務自治
  - 獨立部署
  - 獨立技術選型
  - 獨立資料儲存
```

將這個 Markdown 檔案直接匯入 XMind，就能生成結構清晰的思維導圖啦！

### 四、專業繪圖工具

如果將 AI 與專業繪圖工具結合，可以實現 1+1 > 2 的效果。

```plain
請根據下列內容，生成 draw.io 格式的《程式設計導航原創專案學習路線圖》程式碼：

## 以下是專案學習相關內容
...
```

不過我們會發現，AI 有時候生成的圖片元素會出現排版錯亂、位置對不齊的情況。這時就需要人工進行調整了，有時要改的內容還挺多的，沒點兒畫圖功底還真駕馭不了 AI。

所以雖然 AI + draw.io 這種畫圖方法看起來最強大，實際上還是建議大家根據作圖的型別和複雜度，選擇最合適的方法吧。

## AI 繪圖技巧

掌握了基本的繪圖方法後，魚皮再給大家開個小灶，分享一些高階技巧，幫你更快地畫出更好的圖。

### 技巧 1、提供示例圖讓 AI 模仿

當你看到一個很棒的圖，想要繪製同款時，可以直接截圖給 AI，讓它幫你生成類似的圖。

舉個例子，仿照我提供的系統架構圖進行生成，這種場景適合使用 draw.io 工具。示例 Prompt 如下：

```plain
請根據我提供的系統架構圖，用 draw.io 格式生成類似風格和結構的圖，但內容改為：
- 一個線上教育平臺的架構
- 保持原圖的配色方案和佈局風格
- 包含使用者端、管理端、API 閘道器、核心服務、資料儲存等模組
```

在 Cursor 中執行：

![](https://pic.yupi.icu/1/1748424661404-2d3fbd7d-a563-4ef7-97c1-3bf82bc6fbf1.png)

生成結果如圖，是不是很像？

![](https://pic.yupi.icu/1/1748424880583-92c573bc-fdb2-45d0-b4e0-d2590ea069c5.png)



### 技巧 2、截圖示註，精準修改

如果你對 AI 生成的圖的有些地方不滿意，你可以截圖並在需要修改的地方畫紅圈標註，然後告訴 AI 如何修改，從而實現精準修改。

舉個例子，先對生成的架構圖進行標註，利用截圖工具就可以完成了：

![](https://pic.yupi.icu/1/1748424987920-e61af63a-b688-4cf8-8cd5-e05df1d412c9.png)

然後將標註過的圖片和下列 Prompt 一起傳送給 AI：

```plain
我在圖片上用紅圈標註了幾個地方，請幫我進行修改。
其他部分保持不變，並輸出新的 draw.io 格式的圖片：
1. 第一個紅圈：字型換行了，導致內容顯示不全
2. 第二個紅圈：2 個斜箭頭不是特別好看
3. 第三個紅圈：字型換行了，應該在同一行顯示
```

生成結果如圖：

![](https://pic.yupi.icu/1/1748425471345-3f67f7ee-9de7-4c61-85f6-8b9619631f28.png)

可以發現大多數問題都已經修復了，但缺點是 AI 會重新生成一遍圖片，每次都要等一段時間。運氣不好的話要浪費好多時間在和 AI 鬥智鬥勇上。。。

### 技巧 3：配置專業的系統預設

AI 生成的效果很大程度上取決於輸入的提示詞，所以要讓 AI 畫出更專業的圖，配置一個好的系統提示詞至關重要。在 Cursor 中，我們可以設定專案級別的 Rules 規則，讓 AI 始終遵循你的繪圖規範。

給大家一個專業的架構圖繪製預設，僅供參考：

```plain
# 技術架構圖繪製專家

你是一名資深的系統架構師和技術圖表設計專家，精通各種技術棧和繪圖工具。

## 繪圖原則
1. 所有文字必須使用簡體中文
2. 保持圖表簡潔清晰，避免過度複雜
3. 使用標準的技術圖示和符號
4. 配色專業，一般使用藍、綠、橙等技術感色彩
5. 層次分明，主次關係清晰

## 技術規範
1. 架構圖分層清晰：展示層、閘道器層、服務層、資料層
2. 使用虛線表示非同步呼叫，實線表示同步呼叫
3. 標註關鍵技術棧和中介軟體
4. 新增必要的文字說明，但不要過多
5. 考慮高可用、負載均衡等架構要素

## 輸出要求
1. 根據圖表型別和複雜度選擇 Mermaid、PlantUML 或 draw.io 語法
2. 如果是複雜架構，分模組逐步展示

## 配色方案
- 展示層：藍色系 (#3498db)
- 業務層：綠色系 (#2ecc71)
- 資料層：橙色系 (#e67e22)
- 中介軟體：紫色系 (#9b59b6)
- 錯誤/警告：紅色系 (#e74c3c)
```

進入 Cursor 的 Rules 設定介面，新增一個規則：

![](https://pic.yupi.icu/1/1748425980420-a63384ed-9e6a-4b2c-b736-d8ff2e6ca6ba.png)

將這個預設配置到規則中，可以設定為每次對話都生效，也可以人工按需使用，我這裡設定為人工按需使用：

![](https://pic.yupi.icu/1/1748426020674-a7e0a142-5667-4cdc-a263-2789b395edb6.png)

在 AI 對話時指定 Cursor Rules，AI 就會按照規則來生成圖片，確保輸出的一致性和專業性：

![](https://pic.yupi.icu/1/1748426169737-c9f1fcfd-ec03-4a82-9c02-7874762671f4.png)

生成效果如圖，是不是有內味兒了~

### 技巧 4、組合生成

有時你也不知道哪種方法作圖效果最好，乾脆就同時生成多種不同的繪圖程式碼，再從中挑選。

示例提示詞如下：

```plain
請幫我繪製一個使用者登入流程圖，要求同時生成下列格式的程式碼：
1. Mermaid
2. PlantUML
3. draw.io
```

但是這個技巧大家瞭解一下就好了，實際使用時生成速度會慢很多，成本會比較大。
