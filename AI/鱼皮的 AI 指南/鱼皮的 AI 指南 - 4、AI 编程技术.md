# 魚皮的 AI 指南 - 4、AI 程式設計技術

> ⭐️ 推薦觀看影片版：[https://www.bilibili.com/video/BV1i9Z8YhEja](https://www.bilibili.com/video/BV1i9Z8YhEja/)



最後這部分最重要，作為程式設計師，咱們不光要會用 AI 工具、能利用 AI 開發專案，還要能夠自主開發 AI 專案，把 AI 的能力接入到自己的專案中。

有句話說得好：**AI 時代，所有的傳統業務都值得利用 AI 重塑一遍。**

所以現在很多公司都在招能夠開發 AI 專案的程式設計師，這也是我們的機會。那麼我們要學習哪些知識和技術，才能成為企業招聘的香餑餑呢？

### 1、AI 開發框架

首先從技術角度出發，我們要學習主流的 AI 開發框架，比如 Spring AI、LangChain4j 和 LangGraph。

[Spring AI](https://docs.spring.io/spring-ai/reference/getting-started.html) 和 [LangChain4j](https://docs.langchain4j.dev/intro) 的作用是類似的，都提供了很多現成的方法來幫我們提高開發 AI 應用的效率。比如快速對接大模型、儲存會話上下文、對接向量資料庫實現 RAG 等等。

![](https://pic.yupi.icu/1/1743563460857-95800757-867c-4e8a-ba7c-dd490d09fcbd.png)

區別是 Spring AI 更容易和主流 Java 開發框架 Spring 整合，上手難度較低；而 LangChain4j 更靈活，更適合開發複雜的智慧體。比如在開發一個智慧文件分析系統時，利用 LangChain4j，智慧體能夠自動讀取文件內容，呼叫搜尋引擎獲取相關背景知識，然後根據任務需求，將文件資訊與外部知識結合，生成分析報告。

不過我的建議是，二個都要學，先從 Spring AI 學起，再學 LangChain4j 會更簡單。

[LangGraph](https://www.langchain.com/langgraph) 框架會更復雜一些，它用圖的結構來組織和管理 AI 相關的工作流，適合構建有狀態、多代理的企業級 AI 大專案。打個比方，我們有多個 AI 智慧體，分別負責生成文字、生成圖片、組合文字和圖片，那麼 LangGraph 像是負責人，可以安排這些智慧體的工作順序，一起搞大事。

![](https://pic.yupi.icu/1/1743563530213-250ec646-6247-4b8a-9c5f-f6f642a9652c.png)

用一個表格來總結這幾種技術：

| 場景          | 推薦框架    | 優勢                 |
| ------------- | ----------- | -------------------- |
| Java 企業應用 | Spring AI   | 無縫整合 Spring 生態 |
| 智慧體開發    | LangChain4j | 完整 Agent 工具鏈    |
| 複雜工作流    | LangGraph   | 視覺化編排           |

### 2、AI 整合

開發 AI 應用的前提是要有大模型，但是大模型要消耗算力才能執行，算力就是金錢，從哪兒搞來大模型呢？

2 種方法，使用 AI 雲服務、或者本地部署大模型。

#### AI 雲服務

AI 雲服務就是其他企業為我們部署了 AI 大模型，透過 API 介面的方式提供給我們使用，按量計費。

比如阿里雲百鍊、火山引擎、矽基流動、Open AI 等等。

![](https://pic.yupi.icu/1/1743563631799-46ff94d5-d51b-4dc5-b6cf-dec28bdcdb39.png)

咱們程式設計師需要重點掌握的是：

1. 如何透過 API 接入雲服務？
2. 如何使用 AI 雲服務來建立智慧體和配置引數？
3. 如何選擇合適的雲服務？這就需要關注各家雲服務的計費模式和服務質量
4. 如何更低成本、更穩定地使用雲服務？這就需要我們學習 Prompt 工程和高可用技術



#### 本地部署大模型

本地部署大模型對於很多企業來說也是剛需，資料無需上傳至雲端，能夠有效保障資料的安全性和隱私性，尤其適用於醫療、金融等對資料安全極為敏感的行業。

本地部署大模型其實並不難，只需要使用 [Ollama 工具](https://ollama.com/) 就可以一鍵部署各種主流的開源模型。

![](https://pic.yupi.icu/1/1743563719547-bbed1c54-d1f1-496f-afc2-d755c3538732.png)

唉，但部署大模型的難度不在於技術啊，主要是沒算力啊！不然我也給我們團隊的 [程式設計導航](https://codefather.cn/) 和 [面試鴨](https://www.mianshiya.com) 都來一套魚皮大模型了。



### 3、AI 領域業務

企業中的 AI 業務開發，可不僅僅是來個 AI 對話就夠了，咱們還要掌握幾種更復雜的業務開發，比如 RAG 知識庫、多模態、MCP 服務、ReAct 智慧體。

#### RAG 知識庫

很多公司都有屬於自己的業務知識和文件，會構建自己的問答系統或客服，這就要用到 RAG 檢索增強生成技術。先透過文字嵌入模型，將企業各種文件轉化為向量，存入向量資料庫；當使用者提問時，系統在向量資料庫檢索相關向量資料，找到最相似文件片段，和問題一起輸入大模型處理。這樣一來，大模型能夠基於企業真實資料作答，更準確貼合實際。

![](https://pic.yupi.icu/1/1743563751814-4123230c-c4b8-458f-bf8b-070c7550dd54.png)

關於 RAG 能學的知識可太多了，比如主流的向量資料庫 Milvus 和 PGVector、文件的抽取 / 轉換 / 載入、索引的構建、查詢策略的最佳化等等。**這也是 AI 企業面試的重點！**

#### 多模態

多模態也是主流的 AI 業務場景，即融合文字、影象、音訊、影片等多種不同型別的資料模態，從而提高產品使用的易用性，做出更多有創意的功能。

比如做個智慧導購系統，顧客既可以輸入文字描述想要的商品，系統也能識別顧客上傳的商品圖片，甚至可以理解顧客透過語音提出的購物需求。系統會將這些來自不同模態的資料進行整合處理，在商品資料庫中精準匹配符合要求的商品，並將結果反饋給顧客。

![](https://pic.yupi.icu/1/1743563981663-8c9f4746-03dc-4b32-8477-ba9a9042922c.png)

想開發多模態應用，咱們要學習模態轉換技術，比如文字轉語音（TTS）、語音轉文字（STT）、光學字元識別（OCR）等，不過這些都有現成的工具庫或者雲服務，掌握呼叫方法就行。還可以透過 Spring AI、LangChain 等 AI 開發框架呼叫不同模態的大模型，降低開發難度。

![](https://pic.yupi.icu/1/1743563810137-00b86ee7-2e01-44fd-9c1d-8f4198ef59ee.png)

#### MCP 服務

MCP（Model Context Protocol，模型上下文協議）可以理解為提供給 AI 的各種服務，AI 利用這些服務能夠實現更強大的功能。

![](https://pic.yupi.icu/1/1743563832927-7a2df71f-acc1-47c4-9135-e7d888749dbc.png)

如何在專案中接入別人的 MCP 服務，來增強自己的專案能力；以及如何開發自己的 MCP 服務，讓別人的專案使用，都是必須要學習的。現在使用 Spring AI 等開發框架就可以開發 MCP 服務，而且甚至有高手做了個 [網站](http://mcpify.ai/)，能夠一句話建立自己的 MCP 服務，這真的是泰褲辣。

![](https://pic.yupi.icu/1/1743563865750-bbd02b74-2a56-49a9-963f-e633c1484fe5.png)

#### ReAct 智慧體

ReAct 是一種構建智慧體的開發正規化，目的是打造能夠依據推理結果自主採取行動的智慧體。

它的開發過程會涉及到任務規劃、工具呼叫、互動 I/O、異常處理等知識。尤其是工具呼叫，可以透過 Function Call 或 MCP 實現像天氣查詢、檔案讀寫、網頁執行、資訊檢索、終端命令執行等功能。

![](https://pic.yupi.icu/1/1743563922663-0096045d-8a99-4202-b30d-df77a341e697.png)

就拿開發影片網站為例，使用者說了 “幫我開發一個 Dilidili 影片網站並部署上線” 的指令時，智慧體首先會深入理解任務內容，透過推理梳理出一系列執行步驟，包括明確需求、設計方案、搭建框架、生成程式碼、部署上線等。接下來，智慧體就會呼叫相應的工具來執行這些行動。如果執行過程中遇到問題，還會詢問我們的意見，重新推理並及時調整行動方案。

![](https://pic.yupi.icu/1/1743564028474-638e6414-9a22-4350-80f3-7bf174dd0f77.png)

### 4、AI 工具鏈

最後就是我們開發 AI 專案時可能會用到的一些平臺、工具和類庫了。

#### 低程式碼平臺

比如主流的低程式碼 AI 開發平臺 [Dify](https://dify.ai/)，可以讓我們透過拖拉拽的方式構建自己的 AI 智慧體，建立知識庫並匯入自己的文件，搭建複雜的工作流等等。就哪怕你不會寫程式碼，都能用它搞出複雜的 AI 應用。

![](https://pic.yupi.icu/1/1743564064922-03f6365b-a712-47d9-be55-4867b848a269.png)

#### 工具庫

還有一些開發 AI 智慧體時會用到的工具庫，比如：

- Apache Tika，功能強大的檔案解析器工具庫，支援解析 PDF、Word、Excel、PowerPoint 等各種文件，然後提供給 AI 作為知識。
- Playwright，用於模擬瀏覽器行為的工具庫，AI 需要執行網頁、抓取網頁資料、自動化測試時，它都能派上用場。
- JSON 格式解析庫 GSON 和 Kryo
- HTML 文件解析庫 jsoup

這些類庫基本沒什麼學習成本，要用的時候看文件就好了。

#### 部署工具

專案最終是要部署上線的嘛，所以我們還要掌握高效的部署工具，讓 AI 應用從開發環境順利過渡到生產環境，為使用者提供穩定服務。

如果不在意價格、追求穩定的話，還是優先選擇大廠提供的雲服務來部署專案。但如果是個人學習使用、想快速上線自己的 AI 小應用，可以試試下面這些平臺：

- [Vercel](https://vercel.com/)：適合前端應用的部署平臺，支援自動構建、線上瀏覽、CDN 分發，而且還免費提供可訪問的域名
- [Sealos](https://sealos.io/)：雲原生應用管理平臺，支援 Kubernetes 叢集管理，為 AI 應用提供容器化部署環境，適合需要彈性伸縮的 AI 服務
- [Railway](https://railway.com/)：能讓開發人員輕鬆部署 Docker 容器，無需操心伺服器配置與運維，且自帶自動化構建工具、環境管理能力等

當然，想快速部署服務，上面提到的 Docker 容器化技術也是必須要學習的，就像 APP 的安裝包一樣，能夠輕鬆分發和部署你的應用程式。

![](https://pic.yupi.icu/1/1743564338228-ffc55f7b-7bcd-40df-a10b-4accfb666379.png)

其實我有一種假設，如果 AI 足夠穩定、並且一句提示詞就能生成完整應用的話，是不是可以直接根據 Prompt 來部署專案啊。扯遠了扯遠了，當我沒說吧~
