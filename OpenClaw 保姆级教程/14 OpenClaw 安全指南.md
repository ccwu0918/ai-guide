# OpenClaw 安全指南

> 玩 OpenClaw 的安全紅線和避坑指南

你好，我是魚皮。這是本教程最重要的一篇。OpenClaw 是一個能操作你電腦的 AI 工具，工信部和國家網際網路應急中心都發過安全預警，翻車案例已經一堆了。在享受 AI 帶來便利的同時，安全意識一定要有。



## 真實翻車案例

先給大家看幾個真實的翻車案例，每一個都觸目驚心。

**案例一：Meta AI 安全總監的郵件事件**

Meta 的 AI 安全總監讓 OpenClaw 整理郵箱，特意叮囑 “刪除前先確認”。結果對話太長觸發了上下文壓縮，AI 把 “先確認” 這個指令給忘了，一口氣刪了 200 多封郵件。他連喊 3 次停手都沒用 —— 因為 AI 正在 “專注工作”，根本沒理他。

連 AI 安全專家都翻車了，可見光靠在對話裡叮囑是不夠的。

**案例二：整個 D 盤被刪**

有使用者讓 OpenClaw "修復 workspace"，結果 AI 理解錯了，把整個 D 盤給清了。許可權越大，AI 犯錯的殺傷力就越大。

**案例三：公司內網被入侵**

有員工私自在公司電腦安裝 OpenClaw，沒做任何安全配置。全球有超過 22 萬個 OpenClaw 例項暴露在公網上，大部分沒有開啟身份認證，已經有使用者因為遠端桌面沒設密碼被盜刷信用卡、公司內網被入侵。

這些案例告訴我們一個道理：**AI 不會故意害你，但它犯起錯來可比人狠多了。**



## 安全紅線

下面是 10 條安全建議，每條都是血淚教訓換來的：

1）**開二次確認**

刪除、發郵件這類不可逆操作，一定要在 OpenClaw 設定裡把執行審批開啟，別為了圖省事就 `/elevated on` 全部放行。

2）**給 Token 消耗設上限**

有人一週燒了 14 億 Token，還有人半天扣了 200 塊。OpenClaw 每次對話都會自動注入系統指令和上下文，一個簡單請求就要消耗上萬 Token，一定要在 API 平臺設好每日消費上限。

3）**不要用管理員許可權執行**

有使用者讓 OpenClaw “整理發票，格式不對的刪除”，結果 AI 理解錯了，把整個桌面檔案都給清了。建議用虛擬機器或 Docker 容器隔離執行，給 OpenClaw 劃定專門的工作目錄。在代理的工具管理中按需開關工具，如果只是聊天，關掉 `exec`（執行命令）和 `write`（寫檔案）等危險工具。

4）**別把例項暴露到公網**

自己玩的話本地啟動就行，需要遠端訪問就走 VPN 或 SSH 隧道。同時透過 `channels.whatsapp.allowFrom` 等配置限制誰能跟你的龍蝦對話，防止陌生人發訊息控制你的電腦。

5）**不要讓 OpenClaw 隨便瀏覽來路不明的網頁**

安全公司發現了零點選漏洞，只要讓 OpenClaw 訪問一個惡意網站，攻擊者就能劫持你的本地例項。官方已經緊急發了補丁，一定要保持版本更新。

6）**不要亂裝第三方 Skills**

OpenClaw 的官方技能市場 ClawHub 上被發現超過 800 個惡意外掛，有的偽造系統彈窗騙你輸密碼，有的直接偷瀏覽器密碼和加密錢包。遇到要求你下載壓縮包、執行指令碼的，一律別碰。可以安裝 Skill Vetter 技能來自動審查技能安全性。

7）**金鑰不要明文存放**

API Key、SSH 憑證別寫進 prompt 或配置檔案裡。安全公司測過 OpenClaw 的提示詞注入成功率高達 91%，攻擊者可以誘導 AI 把上下文吐出來。金鑰要用環境變數或金鑰管理工具儲存，`openclaw.json` 和 `auth-profiles.json` 千萬不要分享給別人或上傳到公開倉庫。

8）**堅持用官方最新版本**

已經有黑產團伙在搜尋結果裡推廣假的 OpenClaw 安裝包，誘導使用者下載帶木馬的版本。OpenClaw 近期被國家資訊保安漏洞庫披露了 82 個漏洞，一定要從官網下載並及時更新。

9）**測試環境和生產環境分開**

有人讓 AI 程式設計助手清理配置，結果 AI 誤判環境直接執行了 terraform destroy，194 萬行生產資料全沒了。實驗性操作一定要在隔離的測試環境裡搞。

10）**養成檢視日誌的習慣**

用 AI 最氣的就是它搞砸了你不知道它做了什麼，用 `openclaw logs --follow` 實時檢視操作記錄，出事了才有跡可循。

關於安全配置的更多細節，可以參考官方文件：

- OpenClaw 沙箱模式（Docker Sandbox）：https://docs.openclaw.ai/gateway/sandboxing
- 安全相關配置：https://docs.openclaw.ai/gateway/security
- 執行審批機制：可以配置高危操作（如刪除、安裝）需要人工確認



## 快速安全配置清單

看完上面的內容，你可能會想：道理俺都懂，但具體該怎麼做啊？？？

這裡給你一個快速配置清單，照著做就行：

- 在虛擬機器 / 備用機 / 雲伺服器上執行，不在主力機裸跑。哪怕 AI 把系統搞崩了，也不影響你的正常工作
- 在提示詞（AGENTS.md）裡明確告訴 AI：執行高危操作前必須確認。雖然不能 100% 保證 AI 聽話，但能大幅降低誤操作機率
- 關閉不需要的工具，特別是 EXEC（執行命令）和 WRITE（寫檔案）。如果只是聊天，根本不需要這些工具
- 在 API 平臺設好每日消費上限。各大模型廠商的控制檯都支援設定消費限額，設個你能接受的上限
- 不要讓龍蝦自動安裝技能，人工審查後再裝。關閉 clawhub 和 find-skills 這兩個技能的自動使用許可權
- 定期備份。參考本教程《13 記憶管理與成本控制》中的 Git 備份方法，每天自動備份一次配置
- 保持 OpenClaw 版本更新。官方會持續修復安全漏洞，用老版本就是在裸奔
